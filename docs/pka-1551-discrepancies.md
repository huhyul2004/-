## 1. C-1 의 `m = 2` 기재 — 같은 문단의 레이어 점수로는 `m = 1`

### 요청서 원문 (14쪽, C-1 자바코뿔소 실시예 추가)

> "이때 Damuth 관계식에 따라 K ≈ 148개체가 산출되고, Ne/Nc = 0.2(포유류 사전분포)로 Ne ≈
> 15개체가 추정된다. **예시 레이어 점수는 50, 45 및 95이고, 다수결 형성(m=2) 조건에 의해**
> 종합 위기점수는 약 82로 산출되어 T3(위기) 단계로 분류된다."

### `m` 의 정의

같은 요청서 11쪽(B-2)이 스스로 정의한다.

> "고위험 임계값 **H(예: H = 60)** 를 초과하는 레이어의 수 **m** 에 따라 종합 위기점수
> S_final 을 다음과 같이 보정할 수 있다:
> • m ≥ 2 (다수결 형성): `S_final = α × S_weighted + (1−α) × max(s1, s2, s3)`, α = 0.6
> • m = 1 (단일 신호): `S_final = S_weighted × β`, β = 0.85
> • m = 0 (저위험 일치): `S_final = S_weighted × γ`, γ = 0.70"

`lastwatch_score_full_spec.md` §5.3 (573~598행) 도 `H = 60`, `m = |{k : s_k > H}|` 로 동일하다.

### 대조

| 레이어 | C-1 기재값 | H = 60 초과? |
|---|---:|---|
| L1 EWS | 50 | 아니오 |
| L2 PVA | 45 | 아니오 |
| L3 IUCN | 95 | **예** |

**초과 레이어는 1개이므로 `m = 1` 이다.** C-1 의 `m=2` 기재는 같은 요청서 B-2 의 정의 및
full_spec §5.3 과 일치하지 않는다.

`m = 2` 로 놓았을 때와 `m = 1` 로 놓았을 때의 결과도 다르다.
가중치를 균등하게 잡아 `S_weighted` 를 대략 63.3 (= (50+45+95)/3) 으로 두면:

| 분기 | 식 | 결과 |
|---|---|---:|
| C-1 기재대로 m = 2 | `0.6 × 63.3 + 0.4 × 95` | 76.0 |
| 정의대로 m = 1 | `63.3 × 0.85` | 53.8 |
| C-1 기재 종합값 | — | 약 82 |

세 값이 모두 다르다. (실제 명세서는 신뢰도 동적 가중치를 쓰므로 `S_weighted` 가 63.3 과
다를 수 있어, 이 계산은 분기별 차이를 보이기 위한 것이다.)

### 코드의 같은 계산

코드가 자바코뿔소에 대해 산출하는 레이어는 50 / **35.84** / 95 이고,
`[EWS>70, PVA>50, IUCN>60]` 판정으로 초과 레이어는 IUCN 하나 — **`m = 1`** 이다.
코드는 `raw × 0.85 = 46.65` 를 얻고, 그 뒤 개체수 floor 78 이 이를 덮어쓴다.

## 2. K ≈ 148 — 코드에서 나올 수 없는 값

### 요청서의 K 산출 (6쪽 A-2(3), 14쪽 C-1)

```
population_density(W) = d × W^(-0.75)
K = population_density(W) × habitat_area
d: 포유류 91.2, 조류 55.0 등

자바코뿔소: 91.2 × 2000^(-0.75) = 0.308 개체/km²
            0.308 × 480 km² = 148 개체
```

### 코드의 K 산출 (`lib/tipping-point.ts` 576~579행)

```ts
  // K (환경 수용력) — N0 가 감소 추세면 과거 K 가 더 컸다고 가정
  let K: number;
  if (r < 0) K = Math.max(N0 * 1.5, N0 + 100);  // 회복 가능한 환경
  else K = Math.max(N0 * 1.2, N0 + 50);
```

**입력이 `N0` 와 `r` 의 부호뿐이다. 체중도 서식 면적도 들어가지 않는다.**
자바코뿔소는 `iucn_population_trend = Stable` → `r = 0` → `else` 분기 →
`max(76 × 1.2, 76 + 50) = max(91.2, 126) = 126`.

### 세 값 대조

| 출처 | 산출 방식 | K |
|---|---|---:|
| PKA-1551 C-1 / 발명신고서 (1).docx §8 | Damuth (체중 2,000 kg, 서식면적 480 km²) | **148** |
| `lastwatch_score_full_spec.md` §11.2 | 사용자 지정 | **200** |
| `lastwatch_score_full_spec_v4.md` §12.1 | 지정 200 또는 Damuth 148 병기 | 200 / 148 |
| **코드** | `max(N0 × 1.2, N0 + 50)` | **126** |

### Damuth 가 코드에 없는 것은 아니다

`lib/allometry.ts` 에 Damuth 상수(포유류 91.2, 조류 55.0, 파충류 12.0, 양서류 200)가
구현되어 있다 (`docs/phase2-allometry-constants.md` §3). 그러나
**`evaluateTippingPoint` 가 이를 호출하지 않는다.**
`useAllometric` 플래그는 v4-P2 경로용이고, 현재 DB 를 채운 점수 산출 경로는 v4-P1 이다.

따라서 코드를 그대로 실행하는 한 **148 은 산출되지 않는다.**

## 3. 종합 점수 82 의 출처

요청서의 82 는 근거 없는 값이 아니다. `lastwatch_score_full_spec_v4.md` 부록 B (1288~1294행):

```
자동 산출된 K: 148 (Damuth)
자동 산출된 T_gen: 20.0 (시계열 관측 우선)
자동 산출된 λ_mean: 1.02 (시계열 log-linear fit)
점수: 82.3, Tier: T3
```

> **주목**: K가 v3의 200에서 v4의 148로 감소 → PVA에서 압박 증가 → Consensus 점수 78 → 82 상승.
> Tier는 T3 유지.

즉 **82 는 v4 의 Damuth K = 148 시나리오 값**이고, L2 45 도 그 시나리오의 PVA 값이다
(v3 는 K = 200 에서 L2 37, 종합 78).

| 시나리오 | K | L2 | 종합 |
|---|---:|---:|---:|
| full_spec v3 (K 지정 200) | 200 | 37 | 78 |
| full_spec v4 (Damuth K 148) | 148 | 45 | 82.3 |
| **코드** (`max(N0×1.2, N0+50)`) | **126** | **35.84** | **78.0** |

**요청서 C-1 의 수치는 v4 Damuth 시나리오와 정합한다. 코드와 어긋날 뿐이다.**
그리고 코드의 78.0 은 v3 의 78 과 값만 같고, 레이어 가중합(46.65)이 아니라
개체수 floor 가 만든 값이다 (`docs/population-floor-audit.md` §7).
