# m≥2 max 블렌딩 영향 — 결정 6 (2026-10-03)

엔진 5.1.0 에서 경보 2표 이상(m ≥ 2) 분기를 특허 명세서(full_spec §5.3, PKA-1551 B-2)대로 바꿨다.
같은 날 들어간 결정 8(NaN·Infinity 궤적 제외)의 영향을 따로 떼어 적는다. 사실과 표만 담는다.

| 분기 | 5.0 (변경 전) | 5.1.0 (변경 후) |
|---|---|---|
| m ≥ 2 | `S = S_weighted` (가중합 그대로) | `S = 0.6 · S_weighted + 0.4 · max(s_EWS, s_PVA, s_Ne)` |
| m = 1 | `S_weighted × 0.85` | 그대로 |
| m = 0 | `S_weighted × 0.60` | 그대로 (명세서 γ = 0.70 과의 차이는 결정 대기) |

α = 0.6 은 `V5_SPEC.majorityBlend.alpha`. 경보 문턱(EWS > 70 · PVA > 50 · Ne > 60)은 바꾸지 않았다.
최댓값 ≥ 가중합이므로 **블렌딩은 점수를 올리기만 한다.**

재현:

```
git show 374fdae:data/species.db > /tmp/species.pre.db          # 변경 전 DB (MD5 f881fffea27213e3c02cd48c7c46694a)
tsx research/max_blending_impact.ts /tmp/impact.json /tmp/species.pre.db   # 결정 6·8 분리 측정 (DB 읽기 전용)
```

측정 조건은 DB 를 채우는 `scripts/compute-tipping-points.ts` 와 같다 — 기본 시드(종 ID 해시), `n_sim 1500`, `T 100`.
결정 6 영향은 같은 레이어 점수를 `aggregateConsensus(…, { blendAlpha: 1 })`(블렌딩 없음)로 집계한 값과의 차이,
결정 8 영향은 그 값과 변경 전 DB 저장값의 차이다.

> **정정 (같은 날).** 결정 8 첫 구현(`6e41d4e`)은 궤적이 무효가 되는 순간 `break` 해서, 그 시뮬레이션이 남은 해에 쓰던
> 난수를 건너뛰었다. 그러면 다음 시뮬레이션부터 난수열이 밀려 "무효 궤적을 뺀 효과" 에 "다른 표본을 뽑은 효과" 가 섞인다.
> 그 구현으로 잰 값(무효 620개, 점수 변동 45종 = 상승 31 · 하락 14, 최대 ±0.4)은 그래서 틀렸다. 또 멸종 판정의
> `Number.isNaN(frac)` 검사는 그 앞의 `break` 때문에 실행될 수 없었다.
> 지금 구현은 시뮬레이션을 끝까지 예전과 똑같이 돌리고 무효 표시만 한 뒤 집계에서 뺀다. 아래 수치는 이 구현 기준이며,
> 엔진 조사 에이전트가 원본 엔진에 계측만 붙여 따로 잰 값(95종 · 606개 · 26종 · 하락 0 · 티어 1종)과 정확히 같다.
> 무효 궤적이 없는 215종은 점수·멸종 시각 중앙값·멸종 추정일이 변경 전과 완전히 같다.

## 4. 결정 8 — NaN·Infinity 궤적 제외 (같은 날 반영)

| 항목 | 값 |
|---|---:|
| 무효 궤적이 생기는 종 | 95 (전부 r ≤ 0) |
| 무효 궤적 수 | 606 (해당 종 궤적 142,500 개의 0.43%) |
| 그중 멸종 판정에서 `Math.min(1, NaN) = NaN` 이 나온 궤적 | 152 (66종) — `payload.layer_scores.pva.n_ext_time_nan` |
| 점수 변동 | 26종, 전부 상승 +0.1 ~ +0.2 |
| 티어 변동 | 1종 (뮤티카천일홍 79.8 T3 → 80.0 T4) |
| 멸종 추정일이 바뀐 종 | **71종** (앞당겨짐 61 · 늦춰짐 10, 1년 이상 차이 59종, 범위 −57.6년 ~ +3.6년) |
| 멸종 시각 중앙값(`median_T_ext`)이 바뀐 종 | 75종 |

무효 궤적은 Ricker 식 `exp(r_t·(1 − N/K))` 에서 생긴다. 그해 성장률 r_t 가 음수이고 N 이 K 를 넘으면
지수가 양수가 되어 개체수가 끝없이 불어난다. 결국 `exp` 가 Infinity 로 넘치고 `Infinity − Infinity = NaN` 이 된다.
예전에는 그런 궤적이 멸종 시각 NaN 으로 남아 P_ext 분모에만 들어가거나, NaN → 0 으로 바뀌어 멸종으로 셈해졌다.
5.1.0 은 이런 궤적을 무효로 표시하고 확률·분위수·평균·골든타임에서 뺀다. 유효 궤적 수는 `payload.layer_scores.pva.n_valid` 에 남는다.
양의 되먹임 자체(음의 r_t 에서 N > K 일 때의 폭주)는 모형의 문제라 고치지 않았다 — `docs/decisions-pending.md` 항목 10.

**날짜가 점수보다 크게 바뀐 이유.** 멸종 시각 배열에 NaN 이 섞이면 `sort((a, b) => a − b)` 의 비교 결과가 NaN 이 되고,
정렬은 이를 "같음" 으로 다뤄 NaN 앞뒤를 따로 정렬한다. 그래서 중앙값과 10% 분위수(멸종 추정일의 근거)가 엉뚱한 원소를 골랐다.
NaN 이 빠지면 정렬이 바로잡혀 날짜가 크게 움직인다. 점수에 쓰는 P_ext 는 개수만 세므로 영향이 작다.
