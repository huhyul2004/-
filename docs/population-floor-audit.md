## 1. floor 규칙 전문

`lib/tipping-point.ts` **605~618행**. 신뢰도 압축 직후, 추세 보정 직전에 놓인다.

```ts
  // ===== Bottleneck floor — 절대 개체수 기반 강제 보정 =====
  // P0-2 fix: mature_individuals=NULL 이라도 카테고리 fallback (N0) 에 floor 적용
  // 카테고리 fallback 추정치는 confidence_cap=0.4 로 별도 표기 (다음 단계에서)
  // IUCN Criterion D + Frankham 50/500 + 단일 멸종사건 취약성 반영
  {
    // v5: 카테고리(CR/EN/VU) 기반 floor 전부 제거 — 순수 개체수 임계만 (Frankham 50/500·Criterion D 절대수).
    const N = N0;
    let floor = 0;
    if (N < 50)       floor = 90;  // T4 골든타임
    else if (N < 100) floor = 78;  // T3 후반
    else if (N < 250) floor = 70;  // T3 중반 (자바코뿔소 76)
    else if (N < 500) floor = 60;  // T3 진입
    consensus = Math.max(consensus, floor);
  }
```

**N0 < 100 외에 세 구간이 더 있다. 총 4구간이다.**

| 조건 | floor | 주석의 티어 |
|---|---:|---|
| N0 < 50 | **90** | T4 골든타임 |
| 50 ≤ N0 < 100 | **78** | T3 후반 |
| 100 ≤ N0 < 250 | **70** | T3 중반 |
| 250 ≤ N0 < 500 | **60** | T3 진입 |
| N0 ≥ 500 | 0 (미적용) | — |

`Math.max` 이므로 **점수를 올리기만 하고 내리지 않는다.**
입력은 `N0` 하나 — 등급·추세·분류군은 보지 않는다.
floor 적용 뒤에 추세 보정(급감 +8 / 감소 +4 / 증가 −10)이 이어지므로,
'증가' 추세 종은 floor 값보다 10점 낮아질 수 있다.

`lib/tipping-point.ts` 안의 다른 `floor` 출현(313·327·328·376행)은 전부 `Math.floor` 이며 무관하다.

## 5. floor 규칙의 출처 (git)

`Bottleneck floor` 문자열과 `floor = 78` 은 **`d5525e0`** 에서 처음 등장한다.

| 커밋 | 날짜 | 내용 |
|---|---|---|
| **`d5525e0`** 검증 패치 적용 — Phase 1+2 | 2026-05-04 | floor 도입 |
| `de07a93` P0 블로커 4건 즉시 수정 | 2026-05-06 | 적용 대상을 N0 로 확대 |
| `01fda1b` / `20751de` feat(v5): population-only scoring | 2026-08-01 | 카테고리 기반 floor 전부 제거 |

### `d5525e0` 커밋 메시지에 적힌 이유 (원문)

```
Phase 2 (점수 알고리즘 개선):
- Bottleneck floor — 절대 개체수 기반 강제 보정
  - N<50: floor 90 (T4)
  - N<100: floor 78 (T3)
  - N<250: floor 70 (T3)
  - N<500: floor 60 (T3)
  - CR + N<2500: floor 50
- 추세 보정 — 급감 +8, CR/EN 감소 +4
- mature_individuals 가 실제 데이터일 때만 적용 (추정값엔 미적용)

검증 결과:
- 자바코뿔소(76마리, CR): T1 39.2 → T3 78.0 ✅ HIGH severity 수정
- 바키타돌고래(10마리): T3 → T4 98 (가장 시급)
- 동부저지대고릴라(3800, 감소): T3 → T4 80
- 반달가슴곰(86마리): T2 → T3 (작은 개체수 위험성)

근거:
- IUCN Criterion D: N<50 CR, N<250 EN, N<1000 VU
- Frankham 50/500: Ne<100 단기 위험, Ne<1000 장기
- Single extinction event: N<100 은 안정 추세여도 취약
```

**이유가 커밋 메시지에 명시되어 있다.** 근거 3항목(Criterion D, Frankham 50/500,
단일 멸종사건 취약성)과, 자바코뿔소가 floor 이전에 **T1 39.2** 였고 floor 도입으로
**T3 78.0** 이 되었다는 사실이 함께 적혀 있다.

이번 조사에서 floor 를 끈 자바코뿔소 점수는 **46.6** 이다. 커밋 당시의 39.2 와 다른데,
그 사이 `01fda1b` 가 Layer 3 를 Ne 단독으로 바꾸고 카테고리 floor 를 제거하는 등
계산 경로가 바뀌었다.

### `de07a93` (P0-2) 에 적힌 확대 이유 (원문)

```
[P0-2] CR 종 99.97% T2 수렴 버그
- 근본 원인: bottleneck floor 가 mature_individuals != null 조건이라 wd-* 종에 미적용
- 수정: N0 (카테고리 fallback 포함) 에 floor 적용
- CR Criterion D (Nc<2500) 임계 → 모든 CR 최소 T3 (floor 60)
- 검증: CR 9,474종 중 T3+ 비율 0% → 100%
```

### `01fda1b` (v5) 에 적힌 축소 이유 (원문)

```
- Bottleneck floor: pure population thresholds only (N<50/100/250/500);
  all CR/EN/VU category floors removed
```

즉 floor 는 2026-05-04 에 4구간 + `CR + N<2500 → 50` 으로 도입되었고,
2026-08-01 v5 에서 카테고리 조건이 제거되어 현재의 순수 개체수 4구간만 남았다.

## 7. 자바코뿔소 78 의 이중 의미
