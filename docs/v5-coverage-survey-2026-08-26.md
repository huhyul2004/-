# v5 커버리지 사전조사 — 개체수 없는 종을 구제할 수 있는가

작성 2026-08-26. 재현: `python3 research/analyze_v5_coverage.py` (읽기 전용).
**조사만 했고 `lib/tipping-point.ts` 는 한 줄도 고치지 않았다.**

## 0. 질문

v5 는 실측 개체수가 없으면 점수를 내지 않는다
(`inferPopulationWithSource`: `mature_individuals>0` 또는 `iucn_population_size>0`,
둘 다 없으면 `data_insufficient` → `null`).
IUCN 이 주는 다른 필드로 이 빈칸을 메울 수 있는지 센다.

## 1. 현재 커버리지

| | 종 수 |
|---|---:|
| 전체 | 41,282 |
| EX/EW (무조건 100점) | 631 |
| 개체수 있음 → 점수 산출 | 310 |
| **커버리지** | **941 / 41,282 = 2.3%** |

## 2. 코호트를 셋으로 나눠야 한다

"개체수 없는 3,650종"이라는 표현을 검증한 결과, 결손 종은 실제로 **40,341종**이다.
3,650 에 가까운 숫자는 **IUCN 에서 실제로 데이터를 받아온 종**에 한정했을 때 나온다
(3,475종, EX/EW 포함 시 3,737종). 나머지 36,866종은 Wikidata 에서 긁어온 껍데기라
등급 말고는 거의 아무것도 없어서 조사 대상이 못 된다.

| 코호트 | 정의 | 종 수 |
|---|---|---:|
| L1 전체 결손 | 개체수 없음 + EX/EW 아님 | 40,341 |
| L2 IUCN 동기화분 | L1 ∩ `iucn_synced_at` 있음 | 3,475 |
| L3 위협등급분 | L2 ∩ CR/EN/VU | 617 |

L2 의 75%(2,615종)가 **LC** 다. 티핑포인트 점수가 필요한 종이 아니다.
실제로 값어치 있는 대상은 **L3 의 617종**뿐이다.

## 3. 필드 충전율

L2(3,475종) / L3(617종) 기준. L1 기준 비율은 분모가 40,341 이라 전부 1~8% 로 깔려서 의미가 없다.

| 컬럼 | L2 | L3 | 비고 |
|---|---:|---:|---|
| `iucn_assessment_year` | 100.0% | — | 평가 연도는 전부 있음 |
| `iucn_population_trend` | 98.1% | 89.6% | 추세는 거의 다 있음 |
| `mass_g` | 84.5% | **12.6%** | L2 에선 흔하나 L3 에선 희귀 |
| `iucn_generation_length` | 31.7% | 24.8% | |
| `iucn_criteria` | 21.3% | **92.7%** | L3 에선 거의 다 있음 |
| `summary_ko` | 15.5% | 87.4% | |
| `mass_g_external` | 0.0% | 0.0% | 컬럼만 있고 전부 비어 있음 |

L2 와 L3 의 충전 패턴이 정반대다. `mass_g` 는 L2 에 84.5% 있지만 그 대부분이 LC 종이고,
정작 위협등급 종에는 12.6% 밖에 없다. 반대로 `iucn_criteria` 는 위협등급 종에 92.7% 붙어 있다.
**"체중으로 타감 추정" 경로는 정작 필요한 종에 데이터가 없다.**

## 4. criteria 문자열에서 무엇을 뽑을 수 있나

파서: 대문자 A~E 가 Criterion, 뒤 숫자가 하위번호. `+` 로 이어진 조각은 앞 글자를 상속
(`B1ab(iii,v)+2ab(iii,v)` → B1, B2). 괄호 안 소문자 로마숫자는 구조 판정에 불필요해 제거.
파싱 실패 0 건.

적용한 IUCN 3.1 임계:

| Criterion | 뽑히는 것 | CR | EN | VU |
|---|---|---|---|---|
| C | 성숙개체수 상한 | <250 | <2,500 | <10,000 |
| D | 성숙개체수 상한 | <50 | <250 | <1,000 (D1 한정) |
| A1 | 감소율 하한 | ≥90% | ≥70% | ≥50% |
| A2·A3·A4 | 감소율 하한 | ≥80% | ≥50% | ≥30% |

VU **D2 는 분포(AOO) 기준**이라 개체수 상한이 아니다 — 상한 집계에서 제외했다.
D2 단독이 46회로 단일 문자열 3위라, 이걸 개체수로 오독하면 수십 종이 오염된다.

### 결과 (L3 위협등급 617종)

Criterion 글자별 출현: **A=170, B=355, C=13, D=62, E=1**

| 뽑히는 것 | 종 수 | 비율 |
|---|---:|---:|
| 성숙개체수 **상한** (C 또는 D) | **23** | 3.7% |
| 감소율만 (A) | 170 | 27.6% |
| 둘 중 하나 | 193 | 31.3% |
| **B(분포)뿐이라 개체수와 무관** | **329** | 53.3% |

상한값 분포: `<50` 9종, `<250` 12종, `<2,500` 1종, `<10,000` 1종.
감소율 분포: `≥30%` 46종, `≥50%` 52종, `≥70%` 2종, `≥80%` 65종, `≥90%` 5종.
그중 세대시간까지 있어 **연율 환산이 가능한 종은 111종**.

## 5. 커버리지가 얼마나 오르나 (가정 계산 — 코드 미반영)

| 시나리오 | 커버리지 |
|---|---|
| 현재 | 941 / 41,282 = **2.3%** |
| + C/D 상한을 N0 로 사용 | 964 / 41,282 = **2.3%** |
| + A 감소율까지 사용 | 1,134 / 41,282 = **2.7%** |
| + 체중 타감 추정까지 (L2 전체) | 4,053 / 41,282 = 9.8% |

## 6. 결론

**criteria 경로는 커버리지 수단으로는 실패다.** 위협등급 617종 중 개체수 상한이
나오는 건 23종(3.7%)이고, 전체 커버리지는 2.3% → 2.3% 로 사실상 그대로다.
과반(53.3%)이 Criterion B, 즉 **분포 범위** 기준이라 개체수 정보를 애초에 담고 있지 않다.

여기서 갈리는 선택지는 커버리지가 아니라 성격이다.

1. **정밀도 경로 (23종)** — C/D 상한은 "N ≤ 250" 같은 **부등식**이지 점추정이 아니다.
   v5 의 bottleneck floor 가 이미 `N<50 → 90점`, `N<250 → 70점` 절대 임계로 되어 있어
   상한만으로도 **floor 하한선**은 계산된다. 점수를 새로 만드는 게 아니라
   "최소 몇 점 이상"을 말할 수 있는 종이 23종 생기는 것이다. 숫자는 적지만 논리적으로 안전하다.
2. **감소율 경로 (170종, 세대시간 있는 건 111종)** — A 는 N0 를 주지 않고 r 을 준다.
   현재 r 은 `trendToLambdaV4` 가 추세 문자열(감소/안정)에서 거칠게 만든다.
   A2 ≥80% 같은 정량 감소율 + 세대시간이면 **연율 r 을 실제로 계산**할 수 있어
   EWS·PVA 레이어의 입력 품질이 올라간다. 커버리지는 그대로지만 기존 점수가 정확해진다.
3. **체중 타감 경로** — L3 에 `mass_g` 가 12.6%(78종)뿐이라 위협등급에는 못 쓴다.
   L2 전체로 넓히면 2,919종이 걸리지만 대부분 LC 라 점수를 낼 이유가 없다.

## 7. 반드시 짚어야 할 위험

**v5 가 criteria 를 뺀 건 데이터가 없어서가 아니라 일부러다.** 코드 주석에 명시돼 있다.

> `// v5 (2026-08-01): IUCN 등급/Criterion D 의존 제거 → 유효개체군(Ne) 기반 단독.`
> `//   (순환논증 방지: 우리 점수가 IUCN 등급을 되풀이하지 않도록).`

C/D 상한값은 **등급에서 역산한 값**이다. CR 이라서 `<250` 이 나오는 것이므로,
이걸 N0 로 넣으면 v5 점수가 다시 IUCN 등급의 함수가 된다.
`NOTES.md` 의 H2 검증에서 이미 지적된 **순환 위험**과 같은 문제다.

또한 v4 시절의 `inferPopFromCriterion` (lib/tipping-point.ts:734) 이 **호출되지 않는 채로
아직 파일에 남아 있다.** CR+D → 25~30마리 식으로 상한이 아닌 **점추정**을 돌려주는 구현이라,
되살릴 경우 "≤50" 을 "30" 으로 바꿔 읽는 셈이 된다. 되살린다면 부등식을 부등식으로
다루도록 다시 써야 한다. (이번 조사에서는 손대지 않았다.)

## 8. 권고

커버리지 지표를 올리는 목적이라면 **하지 않는 편이 낫다** — 2.3% → 2.7% 를 얻자고
v5 가 의도적으로 끊어낸 순환을 되살리게 된다.

할 가치가 있는 건 **경로 2(감소율 → r)** 다. 커버리지는 안 오르지만
등급 역산이 아니라 **관측된 감소율**이라 순환에 걸리지 않고, 이미 점수가 나오는 종의
r 추정을 개선한다. 대상은 111종(A + 세대시간 동시 보유).
경로 1(23종)은 점수 산출이 아니라 **"최소 점수 하한" 표기**로 한정하면 순환을 피할 수 있다.

세 경로 모두 **v5 점수 자체를 바꾸는 결정**이라 별도 판단이 필요하다. 이 문서는 조사까지다.
