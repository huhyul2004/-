# 챗봇 평가 — 2026-10-03 (결정 9)

연구자용 챗봇(`/api/chat`)을 평가셋 50문항으로 여섯 번 돌리고, 사이사이 드러난 문제를 고쳤다.
마지막 실행(6차)의 자동 검사와 LLM 채점 결과가 지금 운영에 올라가는 챗봇의 상태다.

## 무엇을 쟀나

| 항목 | 내용 |
|---|---|
| 평가셋 | `research/chatbot-eval/eval_set_v1.json` — 10범주 × 5문항 = 50문항, 16종. 범주: 개체수 · 점수 · 데이터 없음 · 범위 밖 · 예측 · 비교 · 문헌 · 위협 · 절멸 · 출처 |
| 실행기 | `research/chatbot-eval/run_eval.ts` — 운영과 같은 라우트 함수(`app/api/chat/route.ts` 의 POST)를 HTTP 없이 직접 부른다. 모델 `gemini-3.7-flash`, temperature 0.2, 문항마다 1턴 |
| 자동 검사 | 전역 4가지 — 답변 끝 출처 줄 형식 · 숫자 근거(답의 숫자가 컨텍스트·질문·프롬프트에 있는가, 없으면 경고) · 점수 값을 말하면 "자체 계산"·"IUCN 공식 지표 아님" · 숫자를 말하면 출처 표기. 문항별 — 포함·제외 문자열, 정규식, 의미 검사 7가지(데이터 없음 안내 · 범위 밖 안내 · "추정:" · IUCN 링크 · 하한 표시 · 비교 기준 · 계산 근거 경로) |
| LLM 채점 | 채점자 5명이 10문항씩 컨텍스트와 대조 — 근거(0~2) · 규칙(0~2) · 질문에 답함(0~2), 판정(통과 · 경미 · 실패), 사실 오류 여부. 실패·사실 오류 판정은 별도 검증자가 다시 본다 |

## 결과

### 자동 검사

| 실행 | 그 전에 바꾼 것 | 전 검사 통과 문항 | 실패 검사 |
|---|---|---:|---:|
| 1차 | (첫 실행) | 45 / 50 | 6 |
| 2차 | 하한 보강 줄은 점수 값을 말할 때만 · 절멸 종 점수 = 고정값 문구 · LaTeX 금지 규칙 · 검사기 오탐 4건 수정 | 49 / 50 | 1 |
| 3차 | 범위 밖 안내에 숫자 금지 · `$…$` 수식 정리(Pandoc 규칙) | 48 / 50 | 2 |
| 4차 | 3차 채점 반영(연도 근거 · 데이터 모순 자동 표시 · 종별 Ne/N · IUCN 보전 조치 시행 여부 미상) + 적대적 검토 반영(지역 평가 표시 등) | **50 / 50** | 0 |
| 5차 | 레이어 이름 풀이 · 점수의 뜻·티어 구간 줄 · 출처 질문에 모순·비교 기준 함께 | 46 / 50 | 4 |
| 6차 | 모순 줄이 "점수" 를 언급하지 않게 · 점수 단서 규칙을 "점수 값을 말할 때" 로 · 검사기 오탐 3건 수정 | **50 / 50** | 0 (경고 1) |

5차의 실패 4건 중 3건은 검사기 오탐("100/1000" 안의 "100/100" 을 점수로 봄, "데이터베이스(…)에 없습니다" 를 못 잡음)이었고,
1건은 새로 넣은 모순 줄의 "LastWatch 점수(v5)는 …" 문구를 모델이 단서 없이 따라 쓴 것이었다 — 문구를 바꿔 6차에서 사라졌다.
6차 수치는 검사기를 고친 뒤 저장된 답을 다시 채점한 값이다(`--rescore`, LLM 재호출 없음 — 1건이 "데이터베이스에 등록되어 있지 않습니다" 를
못 잡던 검사기 문제). 경고 1건은 비교 답에서 중앙값과의 차(2.0점)를 직접 계산한 것 — 프롬프트는 값을 계산하지 말고 인용하라고 한다.

### LLM 채점

| 실행 | 통과 | 경미한 문제 | 실패 | 사실 오류 |
|---|---:|---:|---:|---:|
| 3차 | 25 | 25 | 0 | 0 |
| 4차 | 33 | 16 | 1 | 0 |
| 6차 (최종) | 31 | 18 | 1 | 1 |

3차 → 4차에서 줄어든 문제 (채점 문구의 키워드로 센 대략치 — 한 문항이 여러 유형에 걸칠 수 있다):

| 유형 | 3차 | 4차 | 고친 것 |
|---|---:|---:|---|
| 다른 줄의 연도를 끌어다 붙임 · "기준 연도 미상" 누락 | 23 | 7 | 등급 줄은 IUCN 등급과 같을 때만 평가 연도, 전체 개체수 줄 출처에 "기준 연도 미상", 프롬프트: 숫자를 인용할 때 그 줄의 대괄호를 그대로 |
| 데이터 모순을 짚지 않음 | 8 | 5 | 서버가 모순을 찾아 컨텍스트에 적음 (성숙 > 전체, IUCN 추세 ↔ 한글 추세) |
| LaTeX 표기 | 3 | 0 | 프롬프트 규칙 + 서버 변환(plainMath) |
| 근거 없는 풀이 | 4 | 2 | 레이어 이름 풀이·점수의 뜻·티어 구간을 컨텍스트에 (5차부터) |

4차의 실패 1건(prov-02, "이 숫자들 출처가 어디야?" — 북극곰)은 추세 모순 줄과 비교 기준 단서를 답에서 빠뜨린 것이다.
5차부터 "출처·근거를 묻는 질문에는 모순·기록 범위·비교 기준 단서를 빠짐없이" 규칙을 넣었다.

6차(최종) 채점은 4차와 비슷한 수준이다 — 같은 평가셋도 실행마다 모델 출력이 흔들려 이 정도 차이는 구분되지 않는다.
6차에서 남은 것:

| 문항 | 판정 | 내용 |
|---|---|---|
| score-05 (한국호랑이 "점수가 어떻게 계산됐는지") | 실패 (검증자 확인) | 계산 단계 값은 모두 맞지만, 출처·근거 질문에 함께 밝히라고 한 "데이터 모순"(성숙 3,140 > 전체 562 · IUCN 추세 ↔ 한글 추세)과 "IUCN 평가 대상: Panthera tigris" 줄을 빠뜨렸다 |
| cmp-04 (북극고래 비교) | 경미 + **사실 오류 1** (검증자 확인) | 비교 기준을 "LastWatch 데이터베이스에 등록된 LC 포유류 54종" 이라고 바꿔 말했다 — 컨텍스트는 "v5 점수가 계산된 54종" |
| 경미 18건 | — | 대부분 데이터 모순 줄을 관련 값과 함께 밝히지 않음(점수·개체수를 말하면서), "기준 연도 미상" 누락, 출처 태그 축약, 질문에 결론 없이 기록만 나열(ext-05) |

모순 줄을 언제 밝힐지는 프롬프트 규칙("관련된 값을 말할 때")에 맡겨 두었고, 서버가 보장하지는 않는다 — 하한 문구처럼
서버 보강으로 강제하려면 답이 어떤 값을 말했는지 판별해야 해서 이번에는 넣지 않았다.

### 사실 오류

세 번의 채점(150개 답변)에서 **사실 오류 판정은 1건**(6차 cmp-04 — 비교 기준을 "등록된 54종" 으로 바꿔 말함)이었다.
컨텍스트에 없는 수치를 지어내거나 숫자를 틀리게 옮긴 답은 없었다. 남은 문제는 표기 규칙(연도·단서·출처 태그의 축약)과
모순·단서를 빠뜨리는 것이다.

## 평가하면서 드러난 다른 문제 — 같은 날 고침

- 서버 하한 보강 줄이 범위 밖 안내에도 붙던 것(1차 off-04) → 점수 **값**을 말할 때만.
- IUCN 기록이 지역(유럽) 평가이거나 아종이 종 단위 평가에 연결된 종 (적대적 검토) → 컨텍스트·페이지에 표시, `docs/decisions-pending.md` 항목 12.
- 절멸 아종(한국늑대)에 종 전체 개체수로 문헌 대조 블록이 붙던 것 → 절멸 종은 문헌 블록 없음.

## 한계

- 1턴 질문만 쟀다. 대화를 이어 가는 경우·프롬프트 주입은 재지 않았다.
- 자동 검사는 문자열·정규식이라 오탐·미탐이 있다 — 여섯 번 실행하며 검사기·평가셋 문제 10건을 고쳤다 (1차 뒤 4 · 3차 뒤 2 · 5차 뒤 3 · 6차 재채점 1).
- LLM 채점도 모델의 판단이다 (사람 검토 아님). 채점 기준은 `lib/chat-context.ts` 의 시스템 프롬프트 규칙이다.
- 평가셋 16종은 전 종을 대표하지 않는다. 모델 출력은 확률적(temperature 0.2)이라 같은 문항도 실행마다 다를 수 있다 —
  4차 50/50 → 5차 46/50 처럼 프롬프트를 조금 바꿔도 흔들린다.
